# Machine Learning Pipeline — Nexora, DOSM Datathon 2026

Forecasts monthly international tourist arrivals to Malaysia for **20 source
markets**, **1–4 months ahead**, and explains which factors (including
geopolitical risk) the model relies on.

> **Scope:** all arrivals figures cover the 20 modelled source markets only (a
> subset of Tourism Malaysia's Top-45 report). They are **not** Malaysia's total
> arrivals from all countries.

---

## Quick start (reproduce everything)

```bash
cd <repo root>
pip install -r requirements.txt
python -m machine_learning.run_pipeline
```

This reads `data/dosm_datathon.db`, trains the model, and writes every table to
`machine_learning/outputs/` and the model to `machine_learning/artifacts/`.
Runtime: ~3–5 minutes. Re-running reproduces identical forecasts (fixed seed).

Run stages individually if preferred:

```bash
python -m machine_learning.models.train            # -> artifacts/lightgbm_final.joblib
python -m machine_learning.models.predict          # -> outputs/historical_actuals.csv, forecast_future_2026.csv
python -m machine_learning.evaluation.evaluate     # -> outputs/backtest_*.csv, covid_*, L3_vs_L4_*
python -m machine_learning.evaluation.explainability  # -> outputs/lightgbm_feature_importance.csv, gpr_*, shap_*
```

## Method in one paragraph

A single **pooled, direct multi-horizon LightGBM** predicts arrivals for each
country at horizons 1–4 (`horizon` is a feature). Features are **availability-
aware**: each predictor is sourced from the freshest month that would actually
have been published at forecast time, using per-variable publication lags
(`config.VARIABLE_LAGS`). The arrivals publication lag is an assumption
(`L_arrivals`, primary = 4 months, sensitivity = 3). The model is validated by a
**rolling-origin backtest** with a row-level, no-future-information rule (a training row is
used only if its target month was known at the simulated forecast date), on a
**normal-period** fold set and a separate **COVID stress-test** fold set, scored
by **MAE and RMSE per horizon**. Baselines (naive-last, seasonal-naive) and a
Ridge model with GPR×country interactions are compared but not deployed.

Full reasoning and every methodology decision: **`docs/METHODOLOGY.md`**.
Every output column: **`outputs/DATA_DICTIONARY.md`**.

## Key results (see outputs/ for exact numbers)

- LightGBM is deployed on the basis of **aggregate MAE pooled across all primary
  backtest predictions** (15,969; Ridge 16,727, Naive-last 17,188,
  Seasonal-naive 22,702) — the criterion matching the single-pooled-model design.
- **It is not best at every horizon.** LightGBM leads at h1-h2; Seasonal-naive is
  marginally best at h3 (21,191 vs 21,504) and Ridge at h4 (20,775 vs 20,983).
  Margins at h2-h4 are 100-313 arrivals, inside fold-level noise.
- Under the COVID structural break, no model reliably beats naive persistence.
- The model-selection conclusion is **stable** across both lag assumptions.

## Important cautions (carry into report & dashboard)

- **Do not** sum arrivals from any table containing a `horizon` column — use
  `historical_actuals.csv` for trends/totals.
- **Do not** present in-sample fit as accuracy — use the backtest tables.
- GPR×country and SHAP-by-country results are **associational model attributions,
  not causal**; the normalized SHAP ratios are noisy for small-base markets.
- Feature alignment used documented publication schedules where available and
  conservative lag assumptions where exact release timing could not be verified.
